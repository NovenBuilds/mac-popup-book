# 场景研发与集成

## 按任务协作

场景实现、共享能力维护、审查和集成按当前任务范围分配，不绑定具体工具、模型或编辑器；同一代理可以承担不同任务。参与者以仓库文件、提交和可复现证据交接，不依赖彼此聊天记录，也不自动派发外部任务。

共同入口为AGENTS.md、PAGE_CONTRACT.md、本文以及统一脚本。各编辑器或代理的专用入口只引用共同规则，不另设职责或验收标准。产品计划及历史验收文档已于2026-11-05迁入 `../planning/`，见 `../project-knowledge/index.md`；原研究目录保留大型证据产物。工程契约、模板和自动测试继续纳入版本管理。

## 独立工作目录

从验收过的main创建 `scene/<id>` 分支，并使用独立Git工作目录；例如在仓库根执行：

```bash
git worktree add ../mac-popup-book-town -b scene/pocket-town main
cd ../mac-popup-book-town
python3 scripts/page.py new pocket-town
python3 scripts/page.py check pocket-town
python3 scripts/page.py preview pocket-town
```

独立工作目录名使用`mac-popup-book-<id>`一类前缀，不与场景id完全同名，避免Swift包路径身份碰撞。

单页预览为独立应用、默认手动展开、使用临时存储且声音默认关闭。真实硬件验证在正式主程序单独进行；两个开发者不应在同一工作目录写文件。

场景分支默认仅修改Scenes/<id>。不要更改共享包注册、主程序或发布清单；公共接口不足时先提交单独的底座变更，所有开发分支更新基线后再使用。

`Templates/Page`包含纯行为模块、独立Worker与测试，生成后必须替换名称和完善中英文文案。仅契约测试页可保留testOnly=true；正式场景须移除，禁止正式服务接受故障注入。

## 新参与者接手

任何代理或开发工具都从AGENTS.md、docs/project-knowledge/index.md、PAGE_CONTRACT.md与本文进入，再读取场景规划和任务交接。按允许修改范围领取任务，不依据工具身份决定职责。

新建独立工作目录只包含基线提交内的文件。若规划、规则或交接文档尚未提交，须显式同步所需文档到新工作目录并记录来源；不能假定它们自动随分支出现，也不能为同步资料擅自提交、合并或推送。不要复制构建缓存、真实存档或其他场景的未提交代码。

## 交接内容

使用TASK_HANDOFF_TEMPLATE.md填写：目标和非目标、允许修改范围、基线提交、契约版本、可复现命令、验收项、代码提交、结果、证据位置、已知限制。不得把“编译通过”写成真实操作或视觉试听通过。

并行开发时，每个场景使用独立的Git工作目录和分支。任务交接记录对应的提交编号，并把工程检查和真机体验证据分开。

## 合并检查

1. 场景行为测试、资源来源、中英文、开合三态与可取消交互通过。
2. `python3 scripts/page.py check <id>`和预览打包通过。
3. 按任务安排审查和验收，核对实际提交及可复现证据，不仅采信实现者总结；真实体验与主观试听单独记录。
4. 集成者合并场景，并单独更新Book/published-pages.json；同次集成严格检查发布列表，不静默跳过失败页。
5. `bash scripts/check.sh`和本机进程集成检查在合并后的代码再次运行。
6. 本地合并与远程推送分开；未经明确授权不推送、不强制覆盖历史。

格式检查可能需要在自己的场景目录执行swift format；全仓格式入口用于集成，不能借格式化修改其他开发分支的文件。

## 2026-10-27 用户确认的进程退场调整

离页时立即释放场景、纹理、音频及业务活动，允许空闲XPC服务暂留，由系统回收；业务仅在当前页推进，翻页期间最多两页持有活动资源。此调整避免macOS频繁重启服务的约十秒限速。崩溃或卡死仍需验证进程身份后终止；退出整书时清理本应用已知服务。不能再以“后台只有一个服务进程”作为验收标准，应检查活动场景资源和业务是否停止。
