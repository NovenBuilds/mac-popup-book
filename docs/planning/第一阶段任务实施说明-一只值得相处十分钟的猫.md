## 1．体验目标与范围

让慢热、温柔的猫有自己的节奏：初见先观察，熟悉后愿意靠近；用户既能获得及时回应，也能什么都不做地看它生活。核心检验是两次独立的十分钟相处，而非十分钟连续点击。

必做：指针靠近、抚摸、轻点邀请、无需拖动的替代操作、自主生活、最小跨次记忆、事件声音。沿用纸猫与现有小屋，不制作完整三维模型、章节、玩具小游戏、摄像头或后台陪伴。

## 2．前置条件与现状差距

当前仅有固定睡醒、出屋、休息、点击问候与回屋，角色交互只有 `greet`（问候）；声音接口仅支持激活与一次播放。复用角度映射、60毫秒平滑、进出屋路径、关联类型姿态和代次回调保护。

开始前保存新工程的三状态截图、动作录屏与基线资源占用；与研究目录的历史已验收应用分别标记。先复验现有问题，既有缺陷另列，不用历史验收代替本阶段验收。

## 3．产品行为规格

### 3.1 输入与回应

| 操作 | 首轮规格 | 回应与限制 |
|---|---|---|
| 指针靠近 | 在猫屏幕投影边界向外扩张40点内停留0.4秒 | 先转头或转耳；每3秒最多触发一次关注，不追踪窗口外指针 |
| 抚摸 | 猫可接触区域按住，累计0.6秒，移动速度10～220点/秒 | 连续传递接触位置与强度，先放松再呼噜；速度过快停止累积，不处罚 |
| 轻点猫 | 按下到释放≤0.3秒，位移≤6点 | 保留问候，动作进行中不排队；长按抚摸后释放不再触发点击 |
| 轻点邀请 | 点击门前小径的已命名可达位置 | 猫看向位置后可走近或用姿态温柔婉拒；不可点击任意地面生成路径 |
| 替代操作 | 聚焦“轻轻摸摸”或“邀请靠近”按钮，按空格/回车 | 一次产生2秒轻抚意图或一次邀请；不依赖精细拖动 |

点是界面逻辑点，不能用显示器像素直接套阈值。命中位置统一为角色局部归一化坐标；指针离开、按键取消、窗口失活时发送接触结束。纸片折叠但角色不适合互动时，操作只得到轻量提示，不缓存到以后播放。

### 3.2 内部状态与节奏

- 短期状态为关注、放松、接触意愿和独处需求，范围均为0～1；属于猫行为，不成为核心框架里的通用“宠物指标”。每项改变有明确原因和上限，不显示数值面板。
- 新用户默认先观察，不逃避。一次有效轻抚至少持续2秒才形成正向经历；连续操作不无限累加。一次相处内相同有效互动的记忆增量最多计3次。
- 接受连续接触6～12秒后，可转为坐下、整理或短暂离开；至少独处8秒后再主动邀请，仍能回应轻点。不使用冷漠、受伤或饥饿惩罚。
- 初始自主行为池：左右观察、整理毛发、伸懒腰、换坐姿、走至另一个休息锚点、安静晒太阳。安静动作持续15～35秒，其他动作后至少间隔8秒；最近两次不选同一动作，主动邀请至少间隔60秒。
- 使用可注入、可设种子的随机源做有约束选择。默认十分钟内至少出现4种自主行为，但不为满足数量强行打断互动。
- 每次输入在下一次行为推进中得到视线或姿态回应；是否靠近由状态决定。缓慢动作不是迟迟不反馈。

### 3.3 仲裁与恢复

暂停、系统睡眠和收合优先于必要移动，其次为直接互动，最后为自主行为。保留85%稳定出屋、75%回屋的迟滞规则。快速合页可压缩返回；中途反向从当前位置继续。

姿态增加视线目标、耳尾、身体朝向、动作阶段与混合权重，渲染只消费姿态。动作过渡默认150～300毫秒；接触结束的呼噜在300毫秒内淡出。后台停止时钟、采样及声音，不累计行为时间，不补播未发生的互动。

### 3.4 最小记忆与声音

第一阶段即建立版本化本地存档v1：会面计数、最后见面时间、已确认的有效互动偏好、熟悉程度。单次有效会面需前台展开相处满60秒，重开窗口不刷计数；相隔30分钟才计为下一次会面。实际行为用单调时钟，日期仅用于描述，不因系统时间回拨减少熟悉程度。

前两次有效会面熟悉程度最多改变问候与靠近概率，不解锁章节。无离线衰减。存档默认位于系统应用支持目录的应用标识子目录；原有校准和声音设置仍保留原键。保存采用临时文件加原子替换，保留上一份备份；损坏时展示非阻断提示并从备份恢复，不能悄悄覆盖未知未来版本。

声库最低配置：轻叫3个变体、呼噜1段无缝循环、脚步/纸张各2个变体。猫叫至少间隔20秒，仅由事件触发；呼噜只跟随已接受抚摸。声音关闭立即停止，重新打开不补播。所有声音保持同一只温柔小猫的听感。

## 5．工程与素材要求

- 核心新增类型化的靠近、接触开始/更新/结束、邀请锚点意图；不放猫专用字段。命中坐标转语义在通用渲染层，猫判断在 `PaperCatBehavior`，界面不计算好感。
- 新增可注入随机源和存档读写边界；猫的记忆载荷有具体可序列化类型，禁止任意字典与 `Any`。通用存储只管理字节、版本错误和原子文件，不解释猫偏好。
- `AudioOutput` 扩展类型化声音请求，区分一次播放、循环句柄、停止与音量过渡；运行层调度，猫模块提供声音标识，平台负责播放。给现有一次声同步迁移调用和测试。
- 小径新增一个邀请锚点、第二休息锚点；场景提供位置与路径，不创建猫。非猫替身必须仍能运行公共调度。
- 第一阶段允许自录与许可明确的录音。优先CC0（尽量放弃版权限制）或允许商用且履行署名的素材；不引入禁止商用或来源不明的声音。原始音频、处理步骤与授权依据分开保存。

## 6．测试与验收

**自动检查：**坐标归一化、拖动/点击互斥、离开与失焦取消、输入节流；每个优先级的中断与反向；固定种子十分钟行为无越界和动作堆积；非猫调度；会面计数、系统时间回拨、存档中断写入/损坏/未来版本；循环声开启停止恰好一次。

**本机验证：**手动与真实角度各十轮开合；触控板和鼠标轻抚、邀请；退出/重启；真实失焦、最小化与睡眠恢复；默认静音及耳机试听。UI响应目标100毫秒内可见，流畅度目标接近60帧，记录实际帧时间与基线差异。

**真实体验：**至少两次独立十分钟，第二次间隔30分钟以上；每次保留至少2分钟完全不操作。记录用户是否主动再次靠近、是否察觉4类自主动作、能否描述一次互动后的变化、是否感觉被催促。不能以“看满十分钟”单独判定通过；若只能靠频繁操作留住注意，回到S1-04调整。

## 7．交付与交接

必交：纸猫陪伴构建、任务关联提交、行为矩阵、声音来源、v1存档样例与自动测试、真实开合记录和两次体验结论。可选增强：更多纸偶微表情，不增加小游戏。外部阻塞：录音素材无合法来源时使用自录/简单合成占位并标注，不能声称最终音色已验收。
