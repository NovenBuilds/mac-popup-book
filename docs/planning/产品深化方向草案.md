# 《林间小屋》产品深化方向草案

日期：2026-10-26。状态：讨论草案，尚非已确认的实施需求。本轮只核对现状、公开接口和本机设备枚举，没有改动应用实现。

## 产品定位建议

保留“合上是一本书，打开是一个有生活的家”的辨识度。在同一座小屋中，通过猫的性格、关系记忆、日常小事件和有后果的互动，形成第一次的惊喜与持续停留的理由。首次展开、单次陪伴、跨日关系分别设计；不把持续使用建立在强制签到、饥饿惩罚或重复合盖上。

当前“第一章·遇见”为硬编码标题，没有章节系统、跨会话关系记忆或内容调度。背景声音为8秒合成循环；猫的行为为有限固定流程。

## 同一场景的故事线

1. 遇见：猫观察用户，允许第一次接近与命名。
2. 安家：用户选择猫垫或一件摆设；猫逐渐形成休息位置偏好。
3. 默契：猫记得用户偏爱的互动方式，陪伴阅读或音乐，小屋保留共同经历的痕迹。
4. 小插曲：猫藏起书签、把纸团带到门前；一次小互动改变以后可见的细节。
5. 一起生活：故事节点完成后仍有自然生活、可重复的温柔回应和少量新事件。

章节代表关系变化，不必更换场景。主线节点之外需要可反复体验的日常行为。给用户的反馈要有延续：一次抚摸改变下一次靠近，一件礼物留在屋里。离开几天后温暖欢迎，不制造欠债感。

## 三维美术与资产准备

推荐先验证“立体书基座＋有厚度的纸景/折叠屋＋真正立体的风格化猫”，再决定是否全部变成体积模型。保留折叠时像书、展开后像家的结构。

先完成角色造型与材质风格参考，以及一只可活动猫的运行样件，再批量制作资产。核心交付包括Blender的.blend源文件、经运行验证的USD/USDZ资产、贴图与商业使用权记录；GLB可按跨平台需要额外导出，不将OBJ静态网格当作可动画角色交付。

猫需要可变形的骨骼绑定、耳尾/眼皮/口部控制及动作衔接。先做睡眠、醒来、伸懒腰、走路、坐下、转身、抚摸回应、倾听与简单律动。小屋与家具需要可拆分的门窗、折线转轴和明确的交互位置。大批采购模型之前，先验证一组完整资产在应用内的导入、动画、落脚和折叠。

技术事实：苹果官方文档将SceneKit标记为macOS 26起弃用，并建议使用RealityKit。原型可保留作行为对照；长期开发前应做RealityKit的小型验证，覆盖骨骼动画、折叠结构、命中交互和声音。弃用不等于当前不能运行，迁移也尚未实施。

## 声音与情境

拆成环境声、动作声、猫的表达三层。环境采用多层、变间隔和自然交叉过渡；动作声跟随落脚、纸片、门窗、抚摸等事件；猫叫与呼噜需要多个样本和符合情境的触发规则。

音乐模式先检测节拍与强弱，触发点头、尾巴拍点、踩步等可衔接动作；稳定律动后再增加舞种。节拍估计不等于准确识别曲风，也不等于自动生成专业舞蹈。

办公与语音模式先允许用户选择，再以粗粒度声音特征辅助。不能仅凭一段声音可靠判断“正在做笔记”“开会”或“聊天”。倾听的表演可以是耳朵转向、探头、在停顿时回应，无需转录会话。系统输出音频与麦克风是不同来源，需要分别授权和说明；自己发出的音效应排除或抑制，避免反馈。

声音与动作必须协调优先级：安静陪伴时减少主动打扰，音乐时呼吸与动作随节奏，用户直接抚摸时优先回应。延续上一段动作，不频繁跳状态。

当前应用进入后台即暂停。若要工作/音乐时持续陪伴，需要新增用户主动开启的低功耗小窗/陪伴模式；不能仅接入声音就声称已具备桌面陪伴能力。

## 传感器：证据与用途

本机本轮只读枚举AppleSPUHIDDevice，发现las（铰链角度）、als（环境光）、accel（加速度计）、gyro（陀螺仪）等设备。仅铰链角度此前已实际读取与应用验收；新传感器的枚举不证明数值读取、精度、采样率或稳定性。

| 输入 | 建议玩法 | 工程边界 |
| --- | --- | --- |
| 铰链 | 打开世界、从缝里窥视、告别 | 已有本机经验，接口未公开，需兼容降级 |
| Force Touch压感 | 抚摸力度、按住呼噜、轻压猫垫 | 应用内压力事件有公开接口；不是重量测量，也不自动提供全局压力 |
| 环境光ALS | 暗下来点灯、猫移向窗边或回屋 | 本机已枚举，需验证未公开读取路径；先提供时间/手动光照替代 |
| 电池与电源 | 插电时小屋灯亮、低电量时猫安静下来 | 常规状态优先使用公开电源接口，不必先读SMC |
| 热状态 | 少动、找阴凉；同时主动降低自身负载 | 公开thermalState可作粗粒度依据；不是室温或CPU精确温度 |
| SMC温度/风扇 | 可选氛围实验 | 机型/键值/权限差异，单独研究，不作基础承诺；无需控制风扇 |
| 加速度计/陀螺仪 | 移动电脑时猫调整重心、树叶轻晃 | 本机已枚举，仍待稳定读取；不鼓励敲击或摇晃电脑 |
| 摄像头/Continuity Camera | 主动开启时挥手、猫看向人 | 需摄像头权限；连续互通相机是iPhone相机输入，不提供Touch ID或指纹数据 |
| Touch ID | 如有私密日记，可用于认证保护 | 只返回认证成败，不提供指纹图像、手指身份或持续触摸信号；不宜当作摸猫输入 |

所有实验输入都应可关闭、可缺失、可退回手动；猫的核心魅力应在不授权摄像头/录音时仍成立。

## 推进顺序建议

第一步：确定猫的性格与三维方向，完成可动画猫＋小屋的技术/视觉样件。
第二步：做一个可连续体验约10分钟的完整小循环——接近、抚摸、回应、安静相处、轻告别，包含跨次记忆与事件音效。
第三步：在同一小屋加入两三个持久故事节点，观察用户是否因关系变化主动回来。
第四步：增加用户主动开启的音乐/办公陪伴模式，先解决低干扰与能耗，再增加输入种类。
第五步：逐个验证光照、IMU、SMC或摄像头实验，不让这些接口拖住核心产品。

验收应关注：用户不被要求时是否主动摸猫、停留后是否发现新行为、下一次是否记得共同经历、连续多次使用是否仍有温暖回应；同时测量空闲功耗、打扰频率、权限拒绝后的完整性与动作衔接。
