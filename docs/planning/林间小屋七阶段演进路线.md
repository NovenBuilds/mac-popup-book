# 《林间小屋》持续演进路线

## 一、产品方向与推进原则

**把《林间小屋》做成一个愿意反复打开、安静相处，也能不断发现新东西的小世界。**

长期主线确定为：**陪伴为主，故事渐进**。章节记录猫与你的关系变化，共同经历留在小屋里；日常相处随时成立，不必完成任务才能获得回应。

体验围绕三种时间尺度展开：

- **第一次打开**：展开一本书、遇见一只猫的惊喜。
- **一次停留**：十分钟里有回应、有变化，也有舒服的安静。
- **多次回来**：猫记得你，小屋保留共同经历，故事逐渐生长。

先验证相处，再升级三维。各阶段都交付一个完整、可体验的版本；通过体验门槛后，复核并更新下一阶段的实施说明再开工。不预先承诺开发周期，不以功能数量代替品质。

## 二、七个阶段

### 第一阶段：一只值得相处十分钟的猫

详细任务与验收见：[第1阶段实施说明](第一阶段任务实施说明-一只值得相处十分钟的猫.md)。

**目标：从“会播放动作”走向“像有自己的生活”。**

围绕接近、观察、邀请、回应、独处、告别，形成一次完整相处。猫有清楚的性格和行为节奏：会主动关注，也会自己晒太阳；用户的互动会影响接下来的反应。

沿用现有纸猫，先改善动作衔接、视线、耳尾、距离感和等待节奏。声音同步改善，先让叫声、呼噜和动作声符合情境。加入少量跨次记忆，让再次打开区别于第一次。

**阶段门槛：**不依靠操作提示或持续点击，用户仍愿意停留约十分钟；能感受到猫在回应自己，也能舒服地什么都不做。重复体验时，不会很快看穿固定播放顺序。

### 第二阶段：一本有触感、有生命的立体书

详细任务与验收见：[第2阶段实施说明](第二阶段任务实施说明-一本有触感有生命的立体书.md)。

**目标：让已经成立的相处，拥有值得靠近观察的表现品质。**

建立统一美术方向，重点验证“纸质书页与折叠场景＋风格化立体猫”。先完成一只猫、一处小屋局部的运行样件，再扩展资产，避免提前批量采购或制作不适配的模型。

升级表情、身体动作、接触与落脚、材质、光影和空间声音；保留书页、折痕、收合机制的辨识度。同步完成长期渲染方案的小规模验证，再决定是否迁移框架。

**阶段门槛：**完全展开、半开、接近收合都自然；猫不会滑步、穿插或突然切姿态；视觉提升不会损害跟手感、互动反馈和运行流畅度。

### 第三阶段：它记得你，故事开始延续

详细任务与验收见：[第3阶段实施说明](第三阶段任务实施说明-它记得你故事开始延续.md)。

**目标：让“再打开一次”产生情感上的延续。**

把“第一章·遇见”发展为同一座小屋中的关系进程，例如遇见、安家、默契。章节通过共同经历推进，而非重复点击或每日签到。

逐步加入称呼、偏好、熟悉程度和共同经历的记忆。变化通过行为与环境呈现：猫更愿意靠近、常坐的位置变化、屋里留下某件物品。久别回来仍然温暖，不制造亏欠或惩罚。

**阶段门槛：**用户能察觉“它记得我们之间发生过什么”；故事节点前后，日常相处确实发生变化；章节完成后仍有可持续的生活。

### 第四阶段：小屋里有值得发现的生活

详细任务与验收见：[第4阶段实施说明](第四阶段任务实施说明-小屋里有值得发现的生活.md)。

**目标：从“与猫互动”扩展为“和猫共同生活在一个地方”。**

深化现有森林、小屋、门窗、小径和屋内物件。加入少量可探索的小事件与有后果的互动，例如猫藏起书签、带回纸团、邀请用户观察窗外。

交互要能组合并留下痕迹，避免每个物件都只是播放一次动画。逐步建立日常事件的变化与节奏，同时保留空白和安静。

**阶段门槛：**多次回来仍可能发现新细节；用户能讲出自己的小经历；小屋更丰富，却没有变成需要不停清理的任务列表。

### 第五阶段：陪你听歌，也陪你安静做事

详细任务与验收见：[第5阶段实施说明](第五阶段任务实施说明-陪你听歌也陪你安静做事.md)。

**目标：让小屋融入真实生活，而不只在专门打开时有价值。**

先提供用户主动选择的安静、音乐、工作陪伴方式，解决小窗展示、后台运行、打扰频率和能耗，再增加声音输入。

音乐互动从可靠的节奏回应开始，逐步发展为不同动作与舞蹈。工作或语音情境先采用用户选择与粗粒度声音特征，让猫表现倾听、专注、好奇；不将声音分类包装成对用户活动的准确理解。

声音体系同步升级为有变化的环境、动作和角色表达；默认安静，权限可选。

**阶段门槛：**用户愿意在做其他事情时保留它；回应贴合情境，长时间运行不令人烦躁；关闭或拒绝声音权限后，核心陪伴依然完整。

### 第六阶段：让现实轻轻走进小屋

详细任务与验收见：[第6阶段实施说明](第六阶段任务实施说明-让现实轻轻走进小屋.md)。

**目标：让设备输入带来有意义的感受，而不是展示传感器数量。**

每次只验证一种输入，按照“稳定性、表达价值、权限成本、设备兼容性”决定是否纳入产品：

| 候选输入 | 值得验证的体验 |
|---|---|
| 触控板压感 | 抚摸力度、轻按回应、持续接触的呼噜 |
| 环境光 | 小屋明暗、窗灯、猫选择晒太阳的位置 |
| 电源与系统热状态 | 作息与氛围变化，同时主动降低应用负载 |
| 加速度计、陀螺仪 | 移动电脑时轻微调整重心与环境响应 |
| 摄像头 | 用户主动开启后的视线或手势互动 |

SMC 温度、风扇等保留为研究候选；Touch ID 只在未来确有认证需求时考虑，不作为摸猫输入。

**阶段门槛：**新增输入确实改善相处体验；硬件缺失、权限拒绝或读数不可靠时可以自然降级。此阶段按能力逐项推进，不阻塞正式发布。

### 第七阶段：成为可以放心长期使用的独立产品

详细任务与验收见：[第7阶段实施说明](第七阶段任务实施说明-成为可以放心长期使用的独立产品.md)。

**目标：让完整体验、工程可靠性与交付品质达到一致。**

集中打磨首次使用、控制方式、无障碍、设置、保存恢复、升级兼容、错误提示与退出体验。完成资产来源和使用权核查，以及安装、签名、分发和更新方案。

通过小范围真实使用，观察首次惊喜、单次停留、多次回访及长期打扰感，修正失衡的互动和内容。正式发布后，以小幅内容与行为更新持续深化同一座小屋。

**阶段门槛：**新用户能独立开始使用；长期运行、睡眠恢复和版本升级可靠；即使没有任何可选传感器权限，也是一款完整、值得留下的产品。

## 三、贯穿各阶段的工程与验收要求

- **守住现有模块边界。**输入负责提供能力，角色负责行为，场景负责空间与环境，表现层负责画面和声音；具体实现由应用组装。
- **接口按阶段需要扩展。**后续逐步引入关系记忆、故事事件、情境输入和资产动画能力；当前不提前设计一套包揽未来的庞大系统。
- **声音、动作、性能持续打磨。**不把音效、动作衔接或资源占用全部留到最后。
- **自动检查与真实体验分别验收。**保持规则、状态转换、保存兼容和降级测试；真实开合、动作观感、试听、长期陪伴由本机体验与小范围用户试用验证。
- **每阶段同时检查首次与重复体验。**既看“第一次是否惊喜”，也看“几次之后是否仍愿意回来”。

3. **验证决策**：先做样件再批量制作。技术分支按文档通过条件选择；未通过采用明确退路。硬件真实接入、模拟检查、设备不支持与尚未验证分别记录。
