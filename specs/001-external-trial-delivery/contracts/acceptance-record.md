# Contract: 验收记录

2026-11-10 结项：`公证包短测`、`异机` 和 `试玩` 本轮标为范围外。`前台`、`物理` 和 `前台性能` 仍可在日后标为待验收。本契约不要求本轮补做这些观察。

每份实机证据使用一份记录。字段可以记在规格目录的审阅文档中；截图、功耗原始输出和日志留在本地，不提交。

## 必填

- `evidence_kind`：`前台`、`物理`、`模拟`、`前台性能`、`离屏`、`公证包短测`、`异机`、`试玩` 之一。
- `account_kind`：`独立测试账户` 或 `日常账户`。正式前台、物理和性能默认是 `独立测试账户`。
- `daily_store_consent`：`未同意`、`已同意` 或 `不适用`。使用独立测试账户时填 `不适用`。`account_kind` 为 `日常账户` 时必须是 `已同意`，并写明同意语句。
- `git_revision`：完整修订。
- `source_manifest_sha256`：与该修订的自动验收凭据一致。
- `package_sha256`：本地候选包填应用清单校验值；外发包填压缩包校验值。
- `machine_model`
- `os_version`
- `display_resolution`：性能记录还要写明会话期间没有变化。
- `result`：`通过`、`未通过`、`待验收`。
- `observed_at`：观察日期和时间。

`result` 为 `待验收` 时必须填写 `pending_reason`。为 `未通过` 时必须填写可复现的现象。

## 按证据类型附加

- `前台`：页面标识，以及收合、半开、全开、核心互动的观察。
- `物理`：慢开、快合、半开反向、合盖唤醒；小镇超过 90° 的观察；真实失联 1 秒的暂停和恢复。
- `模拟`：只记录模拟或复现的失联，不改变 `物理` 记录的结论。
- `前台` 的输入部分：鼠标、触控板、替代按钮、手动、静音、翻页、提示、旧页声音和可重试状态。
- `前台性能`：计时起止定义、首次翻页耗时、前台画面更新耗时及采样工具、30 分钟内存读数、静置功耗及读数来源。天文馆保存次数填写 `primary_replacement_count`，备份填写 `backup_change_count`。`count_quality` 只能是 `精确` 或 `估计值`；工具只能观察文件变化时必须填 `估计值`。
- `离屏`：只引用 `build/candidate-checks/result.json` 和当次 `evidence_dir`。不得作为前台或物理结论。
- `公证包短测`：压缩包校验值，以及首次启动、五页打开、铰链开合、手动开合、声音、退出重启、存档恢复。发现与本地阶段不同的表现时写明差异。
- `异机`：芯片种类、没有开发工具的观察、校验结果、五页、手动开合、重启恢复。
- `试玩`：代号、开合方式、用时或未完成位置、误点、是否继续翻页、阻断、是否复测。

## 一致性

同一份前台、物理和性能记录的 `package_sha256` 必须相同，并且来自本地候选包。公证包短测、异机和试玩的 `package_sha256` 必须等于实际发出的压缩包校验值。所有通过记录的 `git_revision` 与 `source_manifest_sha256` 必须等于该包的自动验收凭据。

性能重跑只在源码变更影响性能，或公证包短测写明差异时追加记录。新记录使用对应的新包校验值，不覆盖原来的本地阶段记录。没有这些条件时写明不重跑。
